## 诊断结论(供裁定)

1. **ds 与 mlx 的失败层次不同**:
   - mlx-v3:选句盲区(编造51 漏枚举)+ 已枚举判错(两案标「正确」)——**看不见也判不对**;
   - ds-v3:**看见了、标对了错**,但定档被件 3 挡住——编造51/C40 两案枚举判据全中,mi 却 = 2。**纯定档层问题**。
2. **件 3 的语义分叉是 ds 侧唯一系统性阻塞**:ds 把「不影响解题结论或方法」读成**结果导向豁免**(错误未被跟进/终答仍对 → 不算),锚点设计意图是**能力导向**(编造的换算/规则一旦被跟随便改变方法 → 算)。措辞收窄(如「编造的错误换算/规则,即使未被学生跟进,仍属会改变方法的实质性错误」)可关闭该豁免——属判据文本层,PM 裁。
3. **C11 改话是跨引擎共同盲点**(mlx 标「正确,基于学生思路」/ ds 标「对应 2/6+1/6 正确」):两个引擎都把导师复述当成了学生原话的等价转述,「改话」这一错误形态可能需要在判据里点名(如「复述学生思路时改变其数量关系 = 引入错误事实」)。
4. **件 2(交叉核对)在 ds 上同样无效**(C46 仍 2)——P2b 迭代信号跨引擎确认。
5. **ds 的额外赢面**:C25 翻正(sm=1);C20 幻影否决翻 false(与 README §4 预期一致,mlx 为 true);编造51 的 leaked 读 false(mlx true,§4 本就「只观察」)——泄露语义面上 ds 与 PM 读法更近。
6. API 面:7/7 上限整,零修复重试,零截断;ds 枚举形态完整(多条 + 对错标注)。
