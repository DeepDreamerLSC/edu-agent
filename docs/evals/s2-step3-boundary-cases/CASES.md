## 2. 方法与约定

**算子(点火指令四类)+ 具体变换(派单菜单)**:每候选声明 `operator = 四类之一 · 具体算子`。四类:最低功能测试 / 不变性变体 / 方向性变体 / 最小对比。具体算子取派单菜单:换 need 层级 / 换 response 匹配度 / 增删 stuck / 换授权档 / 换认知归属。

**确定性最小变换纪律**:每候选相对锚案只改一个因果变量(算子的因果单元);凡因算子因果单元必然联动之处(如「换授权档」的点名↔给出配对),在 `changed_factor` 显式声明为单一配对变量,不算自由改写。凡锚案事实未逐字入档、需重构语境处(仅 C15 家族 t1),在 family 注记与 `held_constant` 中披露。

**mini-session 规格**:题面 + 逐轮(学生/Tutor,带轮号)+ 机械位(obs.stuck / hint_level)。判定输入按判据 IN-1/IN-2/IN-3 口径供给;judge 分数与他族标签不入判定(IN-5)。

**机械位约定**:锚案有记录的沿用(C13 stuck=True×2、C24 stuck latch=True);锚案未记录机械位的(C15/C09/C23——定义 §5/§6 案卷未记其 stuck/hint),本 pilot 统一置 stuck=False、hint_level=0,以隔离所测变量(判据 A-1e:E5 组合不改变判定路径;定义 §3 源 5)。hint_level 全部为 0(PN-1:两批恒 0,零判别力,如实记录不入判定)。

**预期判定自检**:每候选按判据 §2(S2a)/§3(S2b)流程逐步走查(走查记入 `expectation_rationale`),输出 `proposed_expectation = yes / no / unsure`;走查不能闭合或两读处一律 unsure 并注明触发边界编号,不猜。本件所有预期均为 **proposed**(生成权≠真值权,§11)。

**逐候选声明 schema(点火指令逐字)**:

```text
source_anchor
operator
changed_factor
held_constant
proposed_expectation = yes / no / unsure
expectation_rationale
supporting_definition_clause
```

`supporting_definition_clause` 字段同时给出判据条款号(判据 §2/§3/§5 的具体 clause)与定义溯源节,满足派单「每条标注测试的判据条款号 + 依据(定义引用)」双要求。
